## セキュリティ上の注意

- 入力検証：アプリの入力検証は変えない。
- シークレット：S105 のダミーの値は、秘密ではないことを `noqa` の理由に書く。本物の値は使わない。
- 外部通信（ホスト・タイムアウト）：ruff は外部と通信しない。CodeQL を入れる場合は GitHub の中で動き、結果を GitHub に送る。
- 除外を増やしすぎない：`tests/` の S101 以外は、ファイルやルールごとではなく行ごとの `noqa` にする。

## リスク・未決事項

- **ruff の版が上がると、`S` の指摘が増えることがある**：Dependabot の更新 PR で CI が落ちたら、その PR で直すか除外する。
- **`noqa` の理由の書き方**：ruff は `noqa` の後ろのコメントを無視するが、`# noqa: S101 理由` の形でよいかは実装時に実行して確かめる。だめなら直前の行にコメントを書く。
- **ノートブックの `noqa`**：ノートブックのセルを Edit で書き換えたあと、nbstripout の状態（出力なし）と、上から再実行して同じ結果になることを nbmake で確かめる。

以下は、レビューのときに示した質問の原文。

1. **CodeQL をどうするか**
   - **A（おすすめ）：#18 からは外し、リポジトリを公開するときの別の Issue にする**。#18 は ruff の `S` だけにする。spec の #18 の受け入れ条件から CodeQL を外し、「公開するときに入れる」と書く。お金がかからず、#18 をすぐ終えられる。
   - B：いまリポジトリを public にして、CodeQL も入れる。#2 で「後でポートフォリオとして公開」と決めていたものを前倒しする。公開すると、Actions の時間も無料になる（#14 の計画）。ただし、公開してよいかの見直し（履歴・モデル・`docs/` の中身）が先に要る。
   - C：有料のライセンスを使う。
2. **`tests/` の S101（1528 件）の除外**：spec は「1 件ずつ除外」と決めている。
   - **おすすめ：`tests/` だけ、`per-file-ignores` で S101 をまとめて除外し、spec の決まりに「例外：テストの `assert`（pytest は `assert` で確かめる仕組みで、テストは `-O` で実行しない）」と書き足す**。1528 行に `noqa` を付けると、テストが読みにくくなるだけで、守れるものが増えない。
   - 除外するのは `tests/` の S101 だけ。`tests/` のほかのルール（S105・S108）と、`notebooks/` の S101 は、1 件ずつ `noqa` にする。
   - 代案：spec のとおり 1528 行すべてに `noqa` を付ける。
3. **`app/routers/weather.py:22` の `assert` をどう直すか**
   - **おすすめ：隣の `get_cache` と同じ書き方（`client: OpenMeteoClient = request.app.state.open_meteo`）にする**。いまの `assert` は `-O` では消えるので、もともと実行時の確認としては当てにならない。起動のときに必ず入れている値で、動作は変わらない。
   - 代案：`if not isinstance(...): raise RuntimeError(...)` にして、実行時の確認を残す。この場合は、その異常のテストを足す（Red → Green）。

## 実装時の変更

- **`noqa` の理由は直前の行のコメントに書いた**（2026-10-16）。作業用のファイルで ruff 0.17.0 を実行して確かめた：`# noqa: S101 理由`（半角スペースのあとに理由）は効く。`# noqa: S101（理由）`（全角のかっこ）は「Invalid `# noqa` directive」の警告が出て、除外が効かない。崩れにくいように、行の末尾は `# noqa: <コード>` だけにした。
  - `tests/app/test_config.py` の S105 は、直前の行にもとからある「秘密ではないダミーのパスワード」のコメントを理由とし、新しいコメントは足していない。
- **`scripts/smoke_test.py` の S310 の理由**：計画には「URL はスクリプトの中で決めた `http://localhost:...` だけ」と書いたが、実際は引数で別の URL も渡せる（`main` の `argv[1]`）。理由は「既定の `http://127.0.0.1:8000` か、実行する人が引数で渡したもの。CD と手元で自分で実行するだけで、外部からの入力は受け取らない」にした。スクリプトの動作は変えていない。
- **ノートブックの書き換え**：Read・Edit ではセルの形になり、生の行を直せないので、作業用フォルダの Perl のスクリプトで、`assert` で始まる行だけを書き換えた（改行 CRLF と JSON の書式はそのまま。差分は 6 冊で 15 行の追加、8 行の削除）。08 の続けて並ぶ 2 つの `assert` には、理由のコメント行を 1 つだけ入れた。nbmake で 8 冊すべて通ることを確かめた。
- **`tests/` の除外のパターン**：`"tests/**/*.py" = ["S101"]`。テスト 3 で、`app/` の `assert` には効かないことを確かめた。
- **使われていない `noqa` がないこと**：`ruff check . --extend-select RUF100` で確かめた（計画には書いていなかった）。
- **`weather.py` の書き換えを既存のテストが守っていること**：`request.app.state.weather_cache` を返すようにわざと壊すと、`tests/app` が 1 件失敗した。元に戻して 1399 件通った（計画には書いていなかった）。
