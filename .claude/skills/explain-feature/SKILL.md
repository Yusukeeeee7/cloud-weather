# explain-feature：機能の説明を書く

## 入力
- 機能番号（例：`4`）または機能名

## 手順

1. `docs/spec.md` の該当機能、関連コード、テスト、`docs/dev-log.md` の該当エントリを読む。
2. 下の構成で `docs/features/<番号>-<名前>.md` を書く。**コードと dev-log に根拠があることだけ書く**。根拠がない部分は「未記録」と書き、推測で埋めない。
3. 書き終えたら、内容を短く要約して示す。

## 構成

```markdown
# #<番号> <機能名>

## 何をするか
（2〜3文）

## 仕組み
（処理の流れ。必要なら簡単な図を ``` で）
関連ファイル：`app/...`、`tests/...`

## 設計判断
| 判断 | 選んだもの | 他の選択肢 | 理由 |
|---|---|---|---|

## テスト
- 何を確かめているか（正常系・異常系・境界値）
- モック・fixtures の使い方

## セキュリティ・安全性
- この機能で考えたこと

## AI駆動開発での記録（dev-log より）
- 指示とコンテキストの工夫
- AIの誤りと対処
- コスト

## 面接で聞かれそうな質問と答え
- Q. … / A. …（3つ程度）

## 今後の改善
-
```

## 守ること
- コードにない動作を書かない。数値（コスト、MAE、カバレッジなど）は記録からのみ引用する。
- 説明は面接で口頭で話せる長さ・言葉にする。
